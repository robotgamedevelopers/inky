Inky 0.2.5 bounds HTTP request uploads, isolates token counting from generation, and checks the live serving cache and lane lifecycle. These changes build on 0.2.4.

- The server allows up to 128 live connections per peer within its 512-connection total. From acceptance, clients have 10 seconds to send headers and 60 seconds to finish the upload, including chunked bodies.
- Anthropic token counting accepts up to 1 MiB of JSON and 262,144 rendered tokens. It has a dedicated preprocessing permit so a count request leaves generation's permits available.
- Serving lanes track their admission and cache-restore transitions. Trace checks cover retained windows, prefix-tree ownership, handle refresh and pruning. The engine, serving helpers, schedulers and spill storage are split into smaller modules.
- The optional loopback recording gateway labels requests for one OpenCode run and forwards the credentials supplied by each caller. The fleet guides identify the seven-card, 22-turn replay fixture as scripted. A representative recording set and a new sweep are still needed to choose a fleet lane count.
- CI audits the committed Rust dependencies against RustSec advisories and checks that a known vulnerable fixture is rejected. Dependabot is configured to check Cargo dependencies and GitHub Actions weekly.
