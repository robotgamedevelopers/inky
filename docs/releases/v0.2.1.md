Point release of inky fixing live multi-turn Layer 3 KV prefix cache sharing in `inky serve`, prioritizing active decode lanes in `ServeStepPlanner`, fusing Gumbel token sampling into the primary step `MTLCommandBuffer`, and right-sizing `BlockPools` allocation for small-context server instances.

## What changed

### Layer 3 `inky serve` prefix cache activation

- **Layer 3 paged lanes in `inky serve` (`src/serve.rs`, `src/serve/block_cache.rs`, `src/engine.rs`).** Switched `serve` from Layer 2 `Lane::new` (whose sliding-window ring wrap at `>= 1024` tokens invalidated prefix reuse on the first generated token) to `Lane::new_blocked` backed by `Engine::block_pool` and `ServeBlockCache` (`EntryTree` + `RetainedStart` checkpoints with exact LRU eviction and pool-pressure admission guard). Multi-turn coding-agent sessions (`opencode`, `claude`) now achieve `96–99%` cached prompt tokens on follow-up turns (`12–17x` faster follow-up prefill) while admitting `32` concurrent `128K` lanes on M5 Max 128 GB and `16` concurrent `128K` lanes on M5 Pro 64 GB.
- **Right-sized `BlockPools` cap for bounded contexts (`src/engine.rs`, `src/serve.rs`).** `Engine::capped_serve_kv_budget` bounds `serve` KV pool pre-allocation to what `(effective_lanes, ctx)` can usefully address plus prefix-cache headroom, keeping small-context servers (such as `-c 6144 --lanes 1..4` API probes) to `2–4.3 GiB` while leaving full `64K–128K` production budgets unchanged.

### Step scheduling and single-command-buffer sampling

- **Active decode priority before prefill (`src/scheduler.rs`).** `ServeStepPlanner::plan_and_begin_step` runs active 1-token decode batches ahead of prefill chunks until a prefill lane reaches the starvation ceiling (`W`), preventing multi-second decode stalls under mixed prefill/decode load while preserving every `CacheScheduler.tla` bounded-starvation invariant.
- **Single-command-buffer Gumbel sampling (`src/engine.rs`, `src/serve.rs`).** `encode_gumbel_span` and `encode_gumbel_solo` encode Gumbel-max sampling directly onto the step's primary `MTLCommandBuffer` before `commit_step`, eliminating the extra synchronous command buffer commit/wait per generated token.

## Getting started

With Rust installed, `cargo install inky-engine` builds and installs `inky` from crates.io instead.

The model is LM Studio's `Inkling-2-Mini-Q4_K_M.gguf` (or a `native-q8rest-o6` GGUF converted with `tools/inkconvert`), read by default from `~/.lmstudio/models/lmstudio-community/Inkling-2-Mini-GGUF/`; `-m` points at another path.

```sh
gh release download v0.2.1 -R robotgamedevelopers/inky
shasum -a 256 -c SHA256SUMS
mv inky_v0.2.1_darwin_arm64 inky && chmod +x inky
./inky chat
```

To serve over loopback or a private network:

```sh
sudo ./inky tune-memory                    # once, optional: installs inky mode
./inky serve --lanes 32 -c 131072 -n 16384 # on 127.0.0.1:8090
```

[docs/README.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.1/docs/README.md) and [docs/FLEET-SPRINT.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.1/docs/FLEET-SPRINT.md) cover every command, serve flag, and fleet provider recipe.
