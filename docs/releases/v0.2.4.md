Inky 0.2.4 fixes request handling, sampling, and model conversion. It also tightens the checks used to qualify cache, serving, and replay changes.

- Parallel requests can set LoopCD guidance independently from the first generated token. The sampler validates GPU results before returning a token.
- The CLI reports failed Metal steps. Disk attention staging respects buffer alignment, and streamed text recovers after invalid UTF-8.
- The HTTP API preserves conversation transcripts and records generation completion separately from delivery to the client.
- Repeated model conversion preserves inputs and validates converted weights. Memory-helper clients reacquire their lease after a restart.
- Replay measurements separate time to first token from overall request latency. Soak and fault checks require evidence that the workload exercised the condition under test.
- Cache checks compare the retained window against an independent cold run. Trace checks exercise the live serving planner, and golden checks propagate failures from the program producing the output.
