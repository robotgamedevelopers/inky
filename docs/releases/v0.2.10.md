Inky 0.2.10 adds byte-level JSON grammar constraints for tool-call sampling, persistent memory-helper reconnection for `inky serve`, and expanded serving, template, and crash-recovery gates. These changes build on 0.2.9.

- `inky serve` constrains active tool-call JSON bodies (`<|content_invoke_tool_json|>` through `<|end_message|>`) with a byte-level RFC 8259 pushdown automaton (`src/json_grammar.rs`, `Sampler::sample_next_filtered`), enforcing balanced containers, string escapes and UTF-16 surrogate pairs, multi-token UTF-8 continuation validity, declared parameter `required` keys and basic `properties` types, and blocking `<|end_message|>` until the root object completes while keeping ordinary text and thinking on GPU Gumbel sampling.
- `inky serve` maintains a persistent memory-helper lease (`memd::enter_persistent`) so servers started before `sudo inky tune-memory` or across socket-directory replacement automatically acquire and restore the GPU wired-memory reservation, while `count_preprocess` isolation and `max(effective_lanes, 4)` generation preprocessing concurrency are verified under concurrent load (`docs/README.md`).
- `scripts/inky-fleet-serve.sh` aligns its default queue (`128`) and reasoning effort (`low`) with the measured 64-lane sweep (`docs/LANE-SWEEP.md`), and `src/tuning.rs` verifies saturating zero-underflow behavior on small or unreadable memory sizes.
- `inky temp1` verifies fixed-seed `temperature = 1.0` bit-for-bit output equivalence through `ServeBlockCache` + `Lane::new_blocked` (with `INK_TEMP1_SABOTAGE=1`), `tests/spill_http_m5.rs` and `tests/nightly.sh` exercise `SIGKILL` mid-spill-write recovery and orphan `.tmp` sweeping on live `inky serve --spill-dir` restarts, and `src/serve.rs` verifies bimodal `2K` + `64K` tight-pool scheduling with mid-step disconnects and token-for-token agreement with the GGUF's embedded `tokenizer.chat_template`.
