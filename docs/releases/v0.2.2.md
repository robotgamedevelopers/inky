Performance release of inky eliminating per-lane Metal decode dispatch bottlenecks (`9,248 -> 193` per-lane dispatches across 32 lanes), eliminating steady-state CPU block-table rewrites, deduplicating cold turn-1 shared-prefix stampedes via singleflight checkpoint rebind, and overlapping host scheduler bookkeeping with GPU command buffer execution.

## What changed

### 3D-batched Layer 3 Metal decode and dirty block-table sync

- **Shared `BlockedSlab` and 3D-batched decode kernels (`src/engine.rs`, `src/kernels.metal`, `src/prefill.metal`).** Blocked lanes sub-allocate recurrent convolution states (`cs`) and 64-bit GPU block tables (`bt_full`, `bt_win`) from a shared 256-byte-aligned `BlockedSlab` with `Drop`-driven free-list recycling, enabling single-dispatch multi-lane `k_embed_dec`, `k_attn_blk_dec`, `k_attn_combine_dec`, and fused `k_postconv_state_dec` kernels. At 32 active lanes, per-lane decode dispatches drop from **`9,248` to `193` per token** (`-97.9%`, total `encode_decode` dispatches `-88.9%`) and barriers drop from `289` to `193` with bit-identical IEEE-754 arithmetic.
- **Batched Gumbel sampling encoder (`src/engine.rs`, `src/serve.rs`).** `Engine::encode_gumbel_spans` batches multi-lane Gumbel-max sampling into a single `MTLComputeCommandEncoder` (`2` barriers instead of `32` encoders / `96` barriers).
- **Dirty-range incremental `sync_lane_block_table` (`src/blocks.rs`, `src/engine.rs`).** `BlockTable` tracks per-kind dirty block bounds `[dirty_lo, dirty_hi]`, reducing `sync_lane_block_table` to `0` bytes written on the `63` out of `64` steady-state decode steps where no block allocation or prune occurred.

### Turn-1 singleflight prefix deduplication and host/GPU overlap

- **Cold-stampede singleflight prefix rebind (`src/serve/block_cache.rs`, `src/serve.rs`).** When multiple concurrent requests arrive sharing an uncached prefix (`>= 2048` tokens, such as `opencode` or `claude` system+tools prompts at sprint startup), an acyclic `(n_past, -lane)` leader election prefills and seals periodic `EVERY` checkpoints once while follower lanes hold without accruing bypass starvation ticks and immediately rebind via `ServeBlockCache::rebind_if_deeper_match` (with automatic failover on leader cancellation).
- **Host/GPU step overlap (`src/serve.rs`).** `cb.commit()` now overlaps request queue draining, cancelled-job pruning, and waiting-lane `Ev::Alive` SSE keepalives on CPU while the step executes on the Metal GPU.

## Getting started

With Rust installed, `cargo install inky-engine` builds and installs `inky` from crates.io instead.

The model is LM Studio's `Inkling-2-Mini-Q4_K_M.gguf` (or a `native-q8rest-o6` GGUF converted with `tools/inkconvert`), read by default from `~/.lmstudio/models/lmstudio-community/Inkling-2-Mini-GGUF/`; `-m` points at another path.

```sh
gh release download v0.2.2 -R robotgamedevelopers/inky
shasum -a 256 -c SHA256SUMS
mv inky_v0.2.2_darwin_arm64 inky && chmod +x inky
./inky chat
```

To serve over loopback or a private network:

```sh
sudo ./inky tune-memory                    # once, optional: installs inky mode
./inky serve --lanes 32 -c 131072 -n 16384 # on 127.0.0.1:8090
```

[docs/README.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.2/docs/README.md) and [docs/FLEET-SPRINT.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.2/docs/FLEET-SPRINT.md) cover every command, serve flag, and fleet provider recipe.
