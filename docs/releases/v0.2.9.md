Inky 0.2.9 adds multi-row prefill crosspath diagnostics, tightens LoopCD weak-pass and weak-logit verification, enforces native M5 pull-request results for branch protection, and expands nightly GPU and soak gates. These changes build on 0.2.8.

- `inky crosspath` compares finite final-logit bits and private KV and convolution state hashes between a single 17-row prefill span and a split prefill across 12 attention boundaries (`63` through `2,049`), verifying Metal command-buffer completion and failing on a planted `INK_CROSSPATH_SABOTAGE=1` mismatch in the full M5 gate.
- `inky loopcdgate` checks captured weak-pass logits against both the isolated dry probe and the standalone one-pass reference (`weak_loopcd_mismatch`), rejecting nonfinite or mismatched rows. Nightly `tests/loopcd-gate.sh` runs the CLI first-token and paged mixed-lane LoopCD fixtures and requires a planted weak-pass state write (`INKY_TEST_LOOPCD_WRITE_WEAK_STATE=1`) to fail.
- Pull-request CI adds the hosted `m5-pr-result` gate, requiring same-repository provenance and explicit `success` on both `m5-gpu` and `m5-serve` so skipped self-hosted jobs cannot satisfy branch protection, while `scripts/release_ci.py` continues to enforce all main-push CI jobs (`docs/MAIN-NATIVE-RULESET.md`).
- Full and nightly M5 suites pair every GPU gate's exit status with its exact verdict line (`verdict`), run `inky temp1` seeded Gumbel/top-p equivalence with `INK_TEMP1_SABOTAGE=1`, widen `dbatch` to 65 lanes, shorten `memd` Unix-socket paths in `tests/soak_faults.sh`, and schedule the one-hour steady-state soak (`tests/soak.sh`) and fault qualification (`tests/soak_faults.sh`) in `nightly.yml`.
