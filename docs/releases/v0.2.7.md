Inky 0.2.7 expands the TLA+ model and trace-conformance suite, hardens GPU block-table addressing and kernel validation, tightens CLI, disk-tier and tooling checks, and adds GGUF/tokenizer fuzzing and pinned CI dependencies. These changes build on 0.2.6.

- TLA+ safety, action-property and liveness specifications now cover 64-bit packed slab words (`SlabWord`), blocked slab growth and slot zeroing (`BlockedSlab`), vector bank liveness across LoopCD passes (`VecAlloc`), speculative verification rollback (`VerifyRollback`), disk-tier staging and sliding-window rings (`KvDiskTier`, `SwaRing`), and poisoned-slot gate trace replay (`PoisonGateTrace`), with step-bound action conformance across 143 CI-placed checks and mutants.
- Unmapped GPU block-table entries use `u64::MAX` (`CLEARED_GPU_TABLE_ENTRY`) so slab 0's first slot at byte offset 0 is unambiguous. Engine logit accessors hold active `RefCell` borrows against scratch reallocation, LoopCD reserves its weak-pass buffer up front before pool budgeting, unused shader kernels are removed, and sliding-window prefill attention is checked for split invariance.
- CPU top-k sampling partitions candidates in linear time with `select_nth_unstable_by`. CLI commands validate flags and prompt bounds before loading weights, `--kv-disk` creates exclusive mode-`0600` `flock`-locked files without following symlinks and aligns hot-ring splits, and `inkconvert`, `replay` and `load` validate dimensions, quantizer edge cases and clock-driven sweeps.
- GGUF and BPE tokenizer loading return structured errors on malformed metadata, invalid UTF-8 and truncated tables before initializing Metal, backed by a `cargo-fuzz` target and 10,000-case mutation suite. GPU gates verify non-zero sabotage exit codes, and GitHub Actions workflows pin Rust 1.98.1 and action commit SHAs.
