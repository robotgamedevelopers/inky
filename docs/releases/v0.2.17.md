Inky 0.2.17 hardens `--kv-disk` session checkpoint/rollback, paged KV block-pool growth, BPE tokenizer special-token handling, streaming/non-streaming UTF-8 boundary parity, and torn JSONL record recovery.

- `--kv-disk` session rollback (`src/session.rs`, `src/engine.rs`): `Session::checkpoint` now leaves any active disk tier before snapshotting live sliding-window K/V rows, `Session::rollback` leaves any active tier and resets hot-ring and cold-file metadata past `ckpt.n_past` (`Run::tier_rollback`) before restoring `window_kv` and zeroing the uncommitted tail, and `Engine::restore_kv_pos` asserts `swa || pos < cap` to prevent out-of-bounds Metal buffer writes if a full-attention cache shrinks beneath a checkpoint position.
- Paged block-pool growth (`src/blocks.rs`): `BlockPool::grow_by` now validates the `MAX_SLABS` ceiling before allocating slabs and truncates newly pushed slabs on error, keeping subsequent `grow()` / `grow_by()` calls intact after a rejected oversized growth request.
- BPE tokenizer hardening (`src/tokenizer.rs`): `Tokenizer::try_load` skips empty `""` special tokens (`tok_type == 3`) so `encode(..., true)` cannot loop forever with zero progress, excludes special tokens from `tok_to_id` (and filters `!self.is_special(id)` on the whole-piece fast path in `bpe`) so plain-text encoding (`encode(..., false)` and `encode_plain_limited`) cannot emit control token IDs via whole-piece lookup, merges, or byte fallback.
- Reply UTF-8 boundary parity (`src/serve/reply.rs`): `visit_reply` now flushes incomplete trailing UTF-8 bytes with `end = true` across consecutive `<|content_text|>` markers while staying inside the same text block, matching `BlockStream`, `/v1/chat/completions` streaming, and `Renderer::push`.
- Record recovery (`src/record.rs`): `repair_torn_jsonl_file` now loops backward across multiple trailing blank or corrupted lines until the final line parses as a valid `RecordEntry` or the file truncates to `0` bytes.
