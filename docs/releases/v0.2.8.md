Inky 0.2.8 hardens serving request framing, cache ownership and namespace isolation, GPU runtime safety, and continuous verification across TLA+ traces, soak qualification, and release gates. These changes build on 0.2.5.

- **Serving protocol, framing, and stall health.** Pre-authenticated connections are capped (`MAX_UNAUTH_CONNS = 64` on non-loopback binds) with a 5-second header deadline, `TCP_NODELAY`, and bounded unread-body draining before closing early HTTP errors so clients observe `400`/`401`/`413`/`503` responses without TCP `RST`. Chunked uploads accept arbitrarily many sub-cap chunks under `BodyBudget` while bounding chunk-size lines (`8 KiB`) and trailers (`64 KiB`). Generation requests validate JSON types strictly, clamp oversized client `max_tokens` budgets cleanly to lane context, stop immediately on role-header tokens without leaking protocol markers, flush incomplete trailing UTF-8 at section transitions, and overlap bounded queue/cancel/spill host work while Metal command buffers execute. `GET /health` reports `output_tokens`, `process_footprint_bytes`, `starts_spilled`, and pool-pressure deferrals, returning HTTP `503` when a GPU step stalls past its deadline.
- **Prefix cache bounds, spill resilience, and namespace isolation.** `ServeBlockCache` eliminates per-start-point intermediate vector clones on `deepest_start` lookups, caps retained host convolution state (`max_retained_host_bytes`, `max_spilled_starts`) and `EntryTree` growth (`max_nodes`), preserves lane bindings on skipped or failed rebinds, defers rather than failing lanes on recoverable `BlockPool` pressure while failing impossible spans immediately, and bounds synchronous checkpoint spill writes (`30 s` wall-clock budget). Cache lookups and single-flight prefill dedup are keyed by caller principal and optional `X-Inky-Namespace`, with `--isolate-cache` and `--hide-cached-tokens` flags for strict multi-client isolation.
- **Metal runtime, speculative verification, and numerical hardening.** Metal shader compilation sets `MTLMathMode::Safe` explicitly so NaN/Inf guards inside MoE routing, Gumbel/argmax reductions, and `LoopCD` blending cannot be stripped by fast-math optimizations. Non-serving CLI commands, GGUF loading, tokenizer table validation, and `Session` execution return structured errors with zero production `.unwrap()` calls, and `serve` validates CLI flags, GGUF metadata, `--spill-dir`, and `--bind` sockets before entering `inky` memory mode. The engine adds `k_dspark_reject` and fallible `Engine::verify_speculative_gpu` capacity and rejection-sampling guards for speculative verification.
- **Recorder durability, memory helper leases, and tokenizer tables.** Traffic recording (`--record-dir`) opens JSONL files with `O_NOFOLLOW`, handles partial writes and ENOSPC backoff without panicking, and pairs per-turn delivery outcomes with `tools/replay` knee selection (`PickKnee`) and soak disconnect-storm early-abort checks. `inky memd` tags saved wired-memory limits with `kern.boottime`, bounds client descriptors and LaunchDaemon `nofile` limits, and maintains client leases across helper restarts.
- **TLA+ ownership traces, dead-code ledger, and release CI gates.** `ServeOwnershipTrace.tla` binds live `ServeBlockCache`, `BlockPools`, `EntryTree`, and `SpillStore` traces and rejects eight planted serving mutations alongside `PrefixTreeKindMixup` and `ServeBlockCache` `inky poolgate` parity. CI enforces `cargo clippy --locked --bins -- -D warnings`, `rustfmt.toml`/`clippy.toml`, `tests/ignored_tests_ledger.rs`, `tests/dead_code_ledger.rs` (`docs/DEAD-CODE.md`), M5 self-hosted runner availability checks (`scripts/check_m5_runner.py`), and immutable release tag preflight verification (`scripts/release_ci.py`), accompanied by the M5 soak qualification protocol (`docs/SOAK-QUALIFICATION.md`).
