The first release of inky: an inference engine for Thinking Machines' Inkling 2 Mini on Apple silicon, a Rust host with hand-fused Metal kernels that reads the LM Studio GGUF directly.

## What you get

- **One binary for darwin/arm64.** It needs macOS with Metal 4; the prefill GEMMs and prefill attention run on the M5 neural accelerators. The Metal shaders are compiled when the engine starts.
- **The engine.** `inky chat`, `inky run`, `inky bench` and `inky check`, with the exact fp16 K/V cache by default, `--kv-disk` to keep half of that cache on the SSD while generating (bit-identical output, slower generation) and `--kv8` for a half-size cache that is not exact. Logits are checked against llama.cpp in CI.
- **Lanes.** Many streams advance in one batched step, and each expert's weights are read once for all of them. A lane's cache, state and logits are bit-identical whether it runs alone or in a batch.
- **`inky serve`.** Two APIs over the same lanes: OpenAI-compatible chat completions, and the Anthropic Messages API (`POST /v1/messages` and `/v1/messages/count_tokens`), so Claude Code can use inky as its model server. Both stream or not, streaming and not, with tool calls, tool results and `reasoning_content`. Each request gets a lane, earlier turns are rendered exactly as sent, and a client that disconnects cancels its lane. A lane keeps its prompt between turns, and a new request reuses the longest matching prompt prefix held by any lane, so a shared head (a coding agent's system prompt and tools) is processed once. Request bodies may be chunked. Endpoints: `POST /v1/chat/completions`, `POST /v1/messages`, `POST /v1/messages/count_tokens`, `GET /v1/models` (model `inkling-2-mini`) and `GET /health`. It binds to loopback by default; `--key-env` requires a bearer key, and `--queue` bounds the waiting requests, refusing more with 429 and `Retry-After`.
- **Inky mode.** `sudo inky tune-memory` installs a small root helper, `inky memd`. While any inky process runs, the helper raises the GPU wired-memory limit to the value in this machine's tuning; when the last one exits, on a clean exit, a crash or kill -9 alike, it puts the limit back. Without the helper, inky runs with the macOS default limit.
- **Tunings.** One machine's settings, matched by chip and memory and compiled into the binary. This release has one, `m5-max-128gb`; any other machine runs on defaults that leave max(8 GB, 10%) of memory for macOS. `inky_v0.1.0_tunings.tar.gz` holds the `tunings/` folder this binary was built with.

## Getting started

With Rust installed, `cargo install inky-engine` builds and installs `inky` from crates.io instead.

The model is LM Studio's `Inkling-2-Mini-Q4_K_M.gguf`, read by default from `~/.lmstudio/models/lmstudio-community/Inkling-2-Mini-GGUF/`; `-m` points at another path.

```sh
gh release download v0.1.0 -R robotgamedevelopers/inky
shasum -a 256 -c SHA256SUMS
mv inky_v0.1.0_darwin_arm64 inky && chmod +x inky
./inky chat
```

To serve:

```sh
sudo ./inky tune-memory              # once, optional: installs inky mode
./inky serve --lanes 16 -c 131072    # on 127.0.0.1:8090
```

[docs/README.md](https://github.com/robotgamedevelopers/inky/blob/v0.1.0/docs/README.md) covers every command, the serve flags and how to use inky as a provider.
