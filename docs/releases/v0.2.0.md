Major milestone release of inky delivering Layers 3 through 7 (block cache, starvation-bounded scheduler and SSD spill tier, Metal working-set admission, full `claude` and `opencode` sprint harness parity, 64-lane M5 Max knee tuning, and private-network fleet wiring) plus bounded soak and chaos verification.

## What changed

### Layer 3: GPU block cache and prefix tree

- **Append-only 64-position blocks and 64-bit block table.** Window and full-attention KV caches are organized into fixed 64-position GPU pool slabs addressed through a per-lane 64-bit `BlockTable` (`src/blocks.rs`, `src/kernels.metal`, `src/prefill.metal`), with private unsealed tails and zero-on-reuse slot scrubbing.
- **Prefix tree start points.** `PrefixTree` / `BlockBook` (`src/prefix.rs`, `src/blockbook.rs`) retain start points at prompt ends, every 16 blocks, and lane heads so matching prompts resume from the deepest sealed prefix.
- **Verified against TLA+ and Layer 2.** `CacheScheduler.tla`, `BlockLayout.tla`, `PrefixTree.tla`, and `StartTails.tla` traces are checked in CI (`scripts/check-tla.sh`), and `inky poolgate` verifies bit-identical outputs to Layer 2 even with poisoned pool slots.

### Layer 4: Starvation-bounded scheduler, admission, and SSD spill tier

- **Starvation-bounded step planner.** `ServeStepPlanner` (`src/scheduler.rs`) implements the lane lifecycle (`Queued`, `Admitted`, `Restoring`, `Ready`, `InStep`, `Finished`, `Cancelling`, `Cancelled`), enforces a bounded bypass window (`W` ticks), prioritizes longest-waiting and active decode lanes before prefill spans, and honors cancel-in-step barriers.
- **Automatic Metal working-set admission.** `MemoryBudget` computes worst-case per-lane memory directly from Metal's `recommendedMaxWorkingSetSize` minus weights, scratch, and tuning headroom; `AdmissionGate` enforces bounded FIFO waiting and returns HTTP `429 Too Many Requests` with `Retry-After` when full or timed out.
- **Lazy LRU SSD spill tier.** `SpillStore` (`src/spill.rs`, `--spill-dir`, `--max-spill-bytes`) spills unreferenced blocks lazily to SSD with SHA-256 verification, atomic working-set restore reservations, and startup orphan cleanup verified against mid-write `SIGKILL` fault tests.

### Layer 5: Sprint server parity, recording, and observability

- **Real `claude` and `opencode` harness parity.** Verified end-to-end against real `claude` CLI (Anthropic `/v1/messages`, `/v1/messages/count_tokens`, query-string path normalization, `cache_control`, thinking effort, and context clamping) and real `opencode` CLI (OpenAI `/v1/chat/completions`, `stream_options.include_usage`, `inky/inkling-2-mini` model alias, and positive `max_tokens` / `max_completion_tokens` lane-context clamping for default `128000`-token client budgets).
- **Card traffic recording and live timing.** `--record-dir` and `--record-max-bytes` record structured JSONL card turns with bounded file rotation; per-request queue, prefill, and decode timings are logged, recorded, and returned on non-streaming responses via `X-Inky-Queue-Ms`, `X-Inky-Prefill-Ms`, and `X-Inky-Decode-Ms`.

### Layer 6: Candidate machine measurements and 64-lane M5 Max knee

- **Replay benchmark and sweep (`tools/replay`, `docs/LANE-SWEEP.md`).** Measured both M5 Max 128 GB (`574.0 GB/s`, `96.0 tok/s` single-stream decode) and M5 Pro 64 GB (`290.4 GB/s`, `61.6 tok/s`) and swept `8..128` lanes over 7 recorded multi-turn coding cards.
- **64-lane default knee.** Selected **64 lanes** on M5 Max 128 GB (`322.66 tok/s` aggregate, `5.04 tok/s` per lane, `4,259 cards/hr`, `ttft_p95 = 16.3 s`, `60.5 GiB` peak working set) and codified it in `DEFAULT_SERVE_LANES = 64` and `tunings/m5-max-128gb.tuning` (`32` lanes in `tunings/m5-pro-64gb.tuning`).

### Layer 7: Private-network fleet wiring

- **Tailscale private-network serving.** `is_private_ip` allows binding to RFC 6598 (`100.64.0.0/10`) and RFC 4193 (`fc00::/7`) private networks with `--key-env` authentication, paired with `scripts/inky-fleet-serve.sh`, `docs/FLEET-SPRINT.md`, and `tests/fleet_gate.sh`.
- **Cross-machine fleet card qualification.** Real `claude` CLI and Linux-to-macOS Tailscale `opencode` CLI coding-agent cards land cleanly through `inky serve` with `go test ./...` green.

### Layer 8: Bounded soak and chaos verification

- **Fault-injection gates (`tests/soak.sh`, `tests/soak_faults.sh`, `tests/soak_client.go`).** Verified resilience against concurrent client disconnect storms, full-disk `ENOSPC` recording conditions, and `SIGKILL` recovery alongside `inky memd`.

## Getting started

With Rust installed, `cargo install inky-engine` builds and installs `inky` from crates.io instead.

The model is LM Studio's `Inkling-2-Mini-Q4_K_M.gguf` (or a `native-q8rest-o6` GGUF converted with `tools/inkconvert`), read by default from `~/.lmstudio/models/lmstudio-community/Inkling-2-Mini-GGUF/`; `-m` points at another path.

```sh
gh release download v0.2.0 -R robotgamedevelopers/inky
shasum -a 256 -c SHA256SUMS
mv inky_v0.2.0_darwin_arm64 inky && chmod +x inky
./inky chat
```

To serve over loopback or a private network:

```sh
sudo ./inky tune-memory                    # once, optional: installs inky mode
./inky serve --lanes 64 -c 16384 -n 8192   # on 127.0.0.1:8090
```

[docs/README.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.0/docs/README.md) and [docs/FLEET-SPRINT.md](https://github.com/robotgamedevelopers/inky/blob/v0.2.0/docs/FLEET-SPRINT.md) cover every command, serve flag, and fleet provider recipe.
